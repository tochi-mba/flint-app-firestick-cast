# ADR-0017 — additive cockpit message ids 21–27

- **Status:** Accepted
- **Implementation:** In progress; id 26/27 transport directions are being migrated under ADR-0018
- **Date:** 2026-09-06
- **Scope:** Fire TV browser experiment
- **Deciders:** Flint engineering
- **Owners:** Protocol and Windows cockpit workstreams
- **Related:** ADR-0003, ADR-0005, ADR-0012, ADR-0015, ADR-0016, ADR-0018
- **Supersedes:** None
- **Superseded by:** None
- **Amended by:** [ADR-0018](ADR-0018-WINDOWS-PROFILE-BROWSER-LIBRARY.md)

## Context

Tabs, view settings and favicons need to reach the desktop. A personal library needs a secure path
in both directions: native TV actions reach its Windows-profile owner, and a bounded projection
returns to the TV. None of them fit the existing browser messages, and the obvious move — adding
fields to `BROWSER_STATE` — is not available.

Every browser decoder in all three languages ends by asserting there are no trailing bytes. An
appended field is therefore not "ignored by old peers"; it is read as corruption and the entire
frame is rejected. There is no optional-field path in this wire format, by design.

Unknown *type ids* are different: the envelope already carries them opaquely and relays them intact,
which is the extension point the format was built with.

That tolerance is asymmetric in one important way. A receiver that has never heard of a type id does
not silently ignore it — it treats it as a protocol error and closes. So a host cannot probe by
sending.

## Decision

- The cockpit families are **new ids 21–27**, never new fields on 14–20:
  21 `BROWSER_TAB_COMMAND` host→receiver, 22 `BROWSER_TAB_STATE` receiver→host,
  23 `BROWSER_VIEW_COMMAND` host→receiver, 24 `BROWSER_VIEW_STATE` receiver→host,
  25 `BROWSER_FAVICON` receiver→host, 26 `BROWSER_LIBRARY_COMMAND` receiver→host,
  and 27 `BROWSER_LIBRARY_STATE` host→receiver. ADR-0018 owns the library direction rationale.
- They inherit every rule of ADR-0003 and ADR-0005 unchanged: TLS BrowserSession only, payload
  version 2 only, forbidden on the plaintext cast channel, and rejected before dispatch anywhere
  else.
- **Capability is discovered, not declared.** Tabs and view controls become available once the
  receiver sends their state snapshot. Library synchronization becomes available once the receiver
  sends id 26 `RequestSnapshot`; only then may the host answer with id 27. The capability message
  predates all of them and has no field to extend, and probing by sending would disconnect exactly
  the older receivers it was meant to detect.
- Until a family is discovered, its cockpit panel says so and its controls are disabled. It never
  renders empty controls that would look broken.
- `BROWSER_VIEW_STATE` reports **that** a page field has focus and nothing about its contents. The
  cockpit needs to know where typing will land; it has no business knowing what is in the box.
- Favicons are bounded PNG, referenced by id from tab and library rows rather than inlined. Under
  ADR-0018 a saved library row uses zero unless its favicon id is valid in the receiver's current
  epoch; id 25 remains receiver→host until a separate bidirectional design is accepted.
- Rust remains the canonical generator; vectors are regenerated by the deliberate `--ignored`
  command and reviewed as a byte diff.

## Consequences

### Positive

- The desktop can show and drive tabs, zoom and find, while a compatible TV can render the bounded
  projection of the current Windows user's library without a version flag day.
- An older receiver keeps working exactly as before and is never sent something that would close it.
- Panels are honest about what the connected receiver can do.
- The additive rule is now written down, so the next family does not rediscover the trailing-byte
  constraint the hard way.

### Trade-offs

- Seven new ids is seven new codecs in three languages, plus their vectors.
- Discovery means a panel can enable itself slightly after connect rather than immediately. The
  library waits for an authenticated receiver request before any profile data is uploaded.
- The four hardcoded browser-range bounds must move together; missing one is a **security**
  regression, because the message stops being forbidden on the plaintext channel.

## Alternatives considered

| Alternative | Why rejected |
|---|---|
| Append fields to `BROWSER_STATE` | Trailing-byte assertions make it a hard break for every unpatched peer. |
| Bump to protocol v3 | A flag day for a purely additive feature; the envelope already tolerates unknown ids. |
| Use the reserved `flags` word as a feature mask | It is echoed, not honoured; old peers would advertise support they do not have. |
| Declare capability in `BROWSER_CAPABILITY` | Extending it is exactly the breaking change this ADR avoids. |
| Probe by sending a tab command or library state | A receiver that does not know the id closes the session. |
| Send field contents with the editing flag | The cockpit needs the location of focus, not the value; sending the value would leak what is being typed. |

## Invariants and validation

- Rust, C# and Kotlin golden suites must all assert against the **same committed bytes**. The corpus
  contains 75 vectors; implementation remains in progress until every language manifest covers all
  75 and the cross-language gate passes.
- `browser_wire` proves v1 rejection and plaintext-channel rejection for the new ids.
- The four range bounds — `is_browser_type`, `isBrowserType`, `IsBrowserType`, and the golden
  generator's `requires_v2` list — all cover 14–27.
- Direction is not present in encoded bytes. Existing id 26/27 vectors remain byte-identical under
  ADR-0018, while host and receiver loopback tests enforce the reversed sender allow-lists.
- The C# decoder resolves enums reflectively, so a value added to C# alone would pass there and fail
  elsewhere; a golden vector per value is what catches it.

## Revisit criteria

A family that genuinely cannot be expressed as a new id would justify a v3 bump — with a migration
plan, not just a schema. Convenience is not a trigger, and neither is a wish to avoid writing three
codecs.
